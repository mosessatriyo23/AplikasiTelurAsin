# Existing SQLite database upgrade: BLOCKED pending review

`20261023000000_production_safety_baseline` is a **fresh-install baseline**. It creates the current schema from an empty database. Do not run `prisma migrate deploy`, `prisma migrate resolve`, `db push`, or the baseline SQL against an existing database: Prisma cannot infer the undocumented legacy schema safely, and the create statements would conflict with existing tables.

No migration here has been tested against, or generated by inspecting, `prisma/dev.db`. That file must not be used as an upgrade source.

## Operator review required

Before an existing-database migration can be versioned, obtain a sanitized schema-only dump (table/index/foreign-key definitions, no rows) from the exact deployed version and record its application revision. A reviewed additive/rebuild migration must then be tested against a disposable copy. It must at minimum:

- add new columns nullable first where historic truth is unknown;
- set every legacy `Order.fulfillmentState` to `REVIEW` (never infer fulfillment);
- leave every legacy `OrderItem.readyAt` null until an operator-reviewed exact manifest is applied;
- leave `Product.readyStockReconciled` false until stock reconciliation;
- add `RateLimit`, `PaymentAudit`, and required indexes/constraints without dropping data;
- prove transaction rollback on any failed assertion and pass `PRAGMA foreign_key_check` and `PRAGMA integrity_check`;
- define how the reviewed legacy schema is baselined in Prisma migration history before deploy.

A speculative one-size-fits-all `upgrade.sql` is intentionally not checked in: SQLite lacks portable `ADD COLUMN IF NOT EXISTS`, and guessing legacy columns is unsafe. Migration `20261025000000_checkout_review` is versioned for databases that have already applied the reviewed fresh baseline; it is **not** authorization to migrate `prisma/dev.db` or an unbaselined legacy database.
